# 04 智能体协作手册

> 目标：让 Claude、Codex、DSH 子代理与人类在**同一套事实**上协作，减少上下文膨胀与幻觉，
> 而不是让多个模型在聊天里互相“感觉对了”。

## 1. 角色与分工

| 角色 | 建议模型/工具 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| Orchestrator（编排） | DSH 主会话（DeepSeek） | 拆任务、写契约、集成、最终验证、合并 | 不独自写完一个大模块 |
| Architect / Reviewer | Claude Code（已安装，`claude -p`） | 架构评审、ADR 反驳、UX 文案、安全/边界审查 | 默认只读，不改代码、不合并 |
| Builders | Codex（待安装）/ DSH 子代理 | 按任务单实现、写测试、产出证据 | 不跨任务重构、不改契约 |
| QA | DSH 子代理 / 人类 | 对抗测试、格式 fuzz、回归、性能 | 不修业务代码（只报缺陷） |
| Domain Expert | 人类制版师/机修 | 机型参数、面料、试缝、最终可用性 | 不参与代码评审 |
| Product Owner | 人类 | 范围、优先级、商业/许可证决策 | — |

**为什么不让最强模型写全部代码**：长上下文里“写”与“审”由同一模型完成会放大确认偏差。
审查必须换模型/换会话，且只给 diff、契约与验收命令。

## 2. 工作流（每个任务）

```text
Orchestrator 写任务单 docs/tasks/T-xxxx.md
      ↓
Builder 领取 → 建分支 → 实现（≤400 行）+ 测试
      ↓
CI + 自检（命令输出贴进任务单）
      ↓
Reviewer（不同智能体）按清单审查 → 通过/打回
      ↓
Orchestrator 合并 → 更新 state → 关闭任务
```

规则：

- 一个任务一个分支，一个 PR 只做一件事；
- 禁止自我合并；禁止“先合并再补测试”；
- 失败两次即停：写清阻塞点，换方案或升级给人类；
- 任何“完成”必须附命令与输出，不接受“应该可以”。

## 3. 任务单（唯一交接物）

模板见 `AGENTS.md`。补充要求：

- **输入只列必要文件 + 行号范围**，不要附整仓库；
- 验收标准必须可执行（命令、阈值、截图路径）；
- 明确“非目标”，防止智能体自由发挥；
- 任务单不超过一屏；超过则拆分。

## 4. 上下文治理

### 4.1 三层记忆

| 层 | 文件 | 内容 | 更新时机 |
| --- | --- | --- | --- |
| 长期 | `docs/adr/` | 不可轻易推翻的决策 | 决策时 |
| 中期 | `docs/state/current.md` | 当前阶段、进行中任务、阻塞 | 每任务完成 |
| 短期 | `docs/tasks/T-xxxx.md` | 单任务目标/验收/证据 | 任务内 |

聊天记录**不是**记忆。任何未落盘的结论，下一轮就当作不存在。

### 4.2 会话仪式

**开始（≤ 5 分钟）**
1. 读 `docs/state/current.md`；
2. 读任务单；
3. 只打开任务单列出的文件；
4. 复述“我要交什么、怎么验”，有歧义先问。

**结束（≤ 5 分钟）**
1. 跑验收命令；
2. 任务单写 5 行结果 + 证据路径；
3. 更新 `state/current.md`；
4. 列出新发现的未知项。

### 4.3 预算与压缩

- 单任务上下文 ≤ 60k tokens；读取 ≤ 8 个文件 / 2k 行。
- 触发压缩：连续两次失败、跨 3 个无关模块、开始“凭记忆”写 API。
- 压缩方式：写摘要到任务单，开新会话，只带任务单 + 契约 + 相关文件。
- 大文件用 `offset/limit` 分段读，禁止整份粘贴进提示词。

## 5. 防幻觉协议

### 5.1 证据等级

| 等级 | 含义 | 可否作为结论 |
| --- | --- | --- |
| E0 | 模型记忆 / 猜测 | ❌ 禁止 |
| E1 | 官方文档（有 URL + 日期） | ⚠️ 仅辅助，需 E2/E3 交叉 |
| E2 | 源码（path:line + commit） | ✅ |
| E3 | 本机实测（命令 + 输出） | ✅ 最强 |
| E4 | 人类专家签字（工艺/机型） | ✅ 领域结论 |

规则：**外部 API、参数名、单位、格式常量，必须 E2 或 E3**。写之前先 `grep`/读源码/跑探针。

### 5.2 未知项登记

任何无法确认的点写入 `docs/state/unknowns.md`：问题、影响、 owner、截止日、当前证据。
禁止把未知项写成肯定句；代码中用 `TODO(verify):` 标记。

### 5.3 双重验证

- 契约/格式/许可证类结论：两个独立来源（源码 + 实测，或源码 + 官方文档）；
- 不可逆操作（迁移、删除、发布）：人类确认；
- 关键算法：属性测试 + 黄金语料 + 交叉实现对比。

### 5.4 红队审查

Reviewer 必须回答：
1. 这个改动最可能在哪三种输入下出错？
2. 哪些断言没有 E2/E3 证据？
3. 如果验收命令是“假的”（只测了 happy path），会漏什么？
4. 许可证/安全边界有没有被越过？

## 6. 具体工具用法

### 6.1 Claude Code（独立评审）

已安装且已登录（`claude --version` → 2.1.312）。默认只读：

```bash
claude -p "你是独立架构评审。只读以下文件：docs/02-architecture.md, docs/03-roadmap.md, services/digitizer/app/convert.py。按 docs/04-agent-playbook.md 的红队清单输出：阻断项/建议/证据缺口。不要修改文件。" \
  --allowedTools "Read,Grep,Glob" \
  --permission-mode plan \
  --permission-prompts none \
  --max-turns 30 \
  --output-format text
```

> 实测：不加 `--permission-mode plan --permission-prompts none` 时，`claude -p` 可能在目录信任/
> 权限提示处挂起且无输出。评审必须设置超时（≤5 分钟），失败不重试超过一次。
> 评审结果存 `docs/reviews/`，由 Orchestrator 逐条关闭；Claude 不直接改代码。

### 6.2 Codex（待接入）

当前机器未安装 `codex`。接入方式：

```bash
npm install -g @openai/codex   # 需要用户提供 OpenAI 账号/额度
codex --version
```

在接入前，Builder 角色由 DSH 子代理承担；接入后按同一任务单协议工作，不改变流程。

### 6.3 DSH 子代理

适合：并行调研、独立实现、测试补全、文档核对。
提示词必须自包含（子代理看不到主会话）：

```text
任务：实现 T-0101 的 compile_svg 最小版。
只允许修改：services/digitizer/app/compile.py, tests/test_compile.py。
输入契约：docs/contracts/stitch-plan.md；参数证据：docs/research/inkstitch-notes.md。
验收：pytest tests/test_compile.py -q 全绿；不得引入新依赖。
禁止：改 pyproject、改其他服务、凭记忆写 Ink/Stitch 属性名。
返回：diff 摘要 + 测试输出 + 未确认项。
```

## 7. 文件所有权（避免并行冲突）

| 目录 | 默认 owner | 其他人 |
| --- | --- | --- |
| `packages/contracts/` | Orchestrator | 只读；变更需 ADR |
| `services/digitizer/` | Builder A | 只读 |
| `apps/web/` | Builder B | 只读 |
| `docs/` | Orchestrator | 可在任务单指定范围内写 |
| `infra/` | 人类 + Orchestrator | 智能体禁止改生产配置 |

并行任务不得同时改同一文件；需要时先拆接口。

## 8. 常见失败模式

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 越写越偏 | 任务单没有“非目标” | 停止，补任务单 |
| 反复改不对 | 缺少可执行验收 | 先写失败测试，再改 |
| 幻觉 API | 凭记忆写第三方接口 | 降级为 E0，查源码/跑探针 |
| 上下文爆炸 | 整仓库通读 | 按任务单文件清单读，超预算即拆 |
| 两个代理互相覆盖 | 无文件所有权 | 按目录分工，PR 串行合并 |
| “测试通过”但没跑 | 没贴命令输出 | 证据缺失 = 未完成 |
| 许可证污染 | 随手复制 GPL 代码 | 引入前登记来源与许可证 |

## 9. 评审清单（Reviewer 用）

- [ ] 变更范围与任务单一致，无顺手重构；
- [ ] 验收命令真实执行，输出可复现；
- [ ] 新增外部断言有 E2/E3 证据；
- [ ] 边界输入（空、超大、损坏、非法单位）有测试；
- [ ] 契约变更同步 TS/Python/文档；
- [ ] 无密钥、无用户数据、无未授权素材；
- [ ] 性能/成本无明显退化；
- [ ] 回滚方案清楚（开关/版本/迁移）。
