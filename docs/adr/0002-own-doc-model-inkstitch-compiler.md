# ADR-0002：自有文档模型 + Ink/Stitch 作为编译器

- 状态：接受
- 日期：2026-10-30

## 背景

三种整合方式：

- A：自有 JSON 文档 → 编译为 Ink/Stitch SVG → 调 CLI → 针迹计划/机器文件；
- B：把 Ink/Stitch 当库 fork 进后端；
- C：自研制版内核。

## 决策

采用 **A**。Ink/Stitch 运行在独立 worker 容器，锁定 commit；我们维护确定性 SVG 编译器与
参数映射；针迹计划通过一个小的 GPL 扩展序列化。

## 理由

- 边界清晰：业务代码不依赖 inkex 文档对象；
- 可测试：黄金 SVG → DST 的契约测试能锁住行为；
- 可升级：换镜像 + 跑回归即可；
- 可降级：若 CLI 不稳，可在同一容器内改为库调用（B），不改变系统边界。

## 后果

- 需要维护参数映射（属性名、单位、默认值），这是 P1 的核心工作；
- 需要处理 Ink/Stitch 版本差异；
- 不能直接使用 Inkscape GUI 的交互能力（我们本来也不需要）。

## 约束

- 禁止在业务代码里硬编码 Ink/Stitch 属性名；必须来自 `docs/contracts/inkstitch-params.md`；
- 编译器输出必须确定性（无时间戳/随机顺序）。
