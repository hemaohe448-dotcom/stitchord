# ADR-0003：模块化单体 + 异步 worker

- 状态：接受
- 日期：2026-10-30

## 背景

团队规模小、智能体并行开发；过早拆微服务会增加契约与运维成本。

## 决策

- Phase 0–4：一个业务 API（FastAPI，模块化单体）+ 独立计算 worker（digitizer / vectorizer）；
- 通过 Redis 队列解耦重任务；任务状态落 Postgres；
- 只有在出现独立扩缩容/故障隔离需求时，才拆业务服务。

## 后果

- 部署简单，事务边界清晰；
- worker 可独立扩容（GPU/CPU 分离）；
- 需要自律：模块间不得直接跨库访问，必须走服务接口。
