# ADR-0001：项目采用 GPL-3.0-or-later

- 状态：**已接受**（仅服务端调用；当前不对外发行代码）
- 日期：2026-10-30
- 决策者：产品负责人 + 架构

## 决策（2026-10-30 确认）

用户确认：GPL 可接受，因为**只把开源代码放在服务器里运行、调用其能力，不售卖代码**。
因此本项目采用 GPL-3.0-or-later，Ink/Stitch 以独立 worker 方式调用。

边界：
- 托管 SaaS 不构成 GPL 的“分发”，不触发源码提供义务；
- 若未来发行桌面/私有化镜像（含 Ink/Stitch），则必须满足 GPL；
- 不修改/分发 Ink/Stitch 时义务最轻；修改则补丁需公开；
- 当前不引入 CLA/DCO；若未来要双许可/闭源，需要先解决贡献者授权。

## 后果

正面：
- 可以合法复用/修改 GPL 生态，升级路径简单；
- 对开源社区友好，便于吸引制版师贡献预设与测试语料。

负面：
- 若发行桌面/私有化安装包，必须提供对应源码；
- 不能把 Ink/Stitch 静态链接进闭源产品；
- 若未来必须闭源，需要架构级 clean-room 重做（成本高）。

## 备选

1. **闭源 + 独立进程隔离**：SaaS 可行，但桌面发行仍有义务风险；需要律师逐案评估。
2. **MIT/Apache 自研内核**：法律最干净，但要重写绣法/格式，周期以人年计。
